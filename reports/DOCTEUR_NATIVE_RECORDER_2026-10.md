# DOCTEUR NATIVE RECORDER — RECORDER-1: local video recording core + recording store (2026-10-16)

RECORDER-1 builds the foundation that REC-DL-1 lacked (`REC_DL_1_BLOCKED / NO_RECORDER_EXISTS`):
- a real local video recorder: browser capture → chunked transfer → recording store;
- one source of truth: the Recorder catalogue;
- a server-generated `recordingId`;
- atomic finalization, integrity, deletion and crash recovery;
- a safe-open primitive ready for REC-DL-1.

What it does not include:
- **No product wiring.** The route factory is not registered in `server.js`, and `App.tsx` / `client.ts` do not import the panel, because those are KG-mixed protected files.
- **No download button.** REC-DL-1 is not resumed.
- **No new capability.** FFmpeg is not used.

**Storage layout:**

```
<root>/recorder.sqlite              metadata only — never a video blob
<root>/partial/<recordingId>.partial  bytes being captured — never READY
<root>/files/<recordingId>.<webm|mp4> finalized ORIGINAL recordings
```

## 3. Recording model and recordingId

- **`recordingId`** = `rec_` + 32 hex characters (128 random bits). It is generated by the service and validated everywhere by the strict regex (also enforced by the DB `CHECK`). The client never chooses an id, a path or an extension.
- **Public view** (no path, no key): `recordingId`, `type`, `source`, `status`, `title`, `createdAt`, `startedAt`, `stoppedAt`, `durationMs`, `mimeType`, `sizeBytes`, `width`, `height`, `hasAudio`, `metadataSource: CLIENT_REPORTED`, `checksumSha256`, `filename`, `error`, `recoverable`, `chunkCount`.
- **Server-only:** `storage_key` (`files/<id>.<ext>`) and `partial_key`.
- **Types:** `SCREEN`, `CAMERA`, `SCREEN_WITH_MIC`, `CAMERA_WITH_MIC`.
- **Title:** NFC, ≤ 120 characters; control characters (CR, LF, U+2028 / U+2029) are refused; `\ / : * ? " < > |` become spaces.
- **Download name** for REC-DL-1: title + real extension through `safeDisplayName`. Reserved names fall back to `enregistrement.<ext>`, and Unicode is kept.

## 4. Format (MIME honesty)

- **Browser preference** (deterministic, `MediaRecorder.isTypeSupported`):
  1. `video/webm;codecs=vp9,opus`
  2. `video/webm;codecs=vp8,opus`
  3. `video/webm`
  4. `video/mp4;codecs=avc1,mp4a.40.2`
  5. `video/mp4`

  WebM comes first: open codecs, and a streamed container that stays readable when a capture is cut. MP4 is only a fallback (e.g. Safari).
- **Actually selected** in Docteur's Chromium (browser suite): `video/webm;codecs=vp9,opus` → extension **`.webm`**.
- **Server:**
  - The declared MIME must be `video/webm` or `video/mp4` (codecs allowed).
  - The **first chunk is sniffed** (`sniffMedia`: EBML → webm, `ftyp` → mp4) and must match the declared container; otherwise `MIME_MISMATCH` → FAILED.
  - The extension comes from the sniffed container. A WebM is never stored or labelled `.mp4` (tested both ways).
- **No transcoding, no FFmpeg:** the stored file is byte-for-byte the MediaRecorder output (tested).

## 5. Capture protocol, chunking, memory

**Steps:**

| Call | Effect |
|---|---|
| `createSession({ type, title, mimeType })` | → `{ recordingId, sessionToken, limits }` (PREPARING); `<id>.partial` is created with an exclusive open (`wx+`) |
| `markStarted` | → RECORDING |
| `appendChunk({ seq, bytes })` | **positional** write at the received offset |
| `finalize({ durationMs?, width?, height? })` | → READY \| FAILED |
| `cancel` | → CANCELLED, partial removed |

**Protocol rules:**
- **Session token:** 256 bits, of which only its SHA-256 is kept (`timingSafeEqual`). It travels in the `x-docteur-recorder-session` header, never in the URL. The `recordingId` alone cannot inject chunks.
- **Order:** `seq` must be exactly 0, 1, 2… A gap gives `CHUNK_GAP`, an older seq `CHUNK_OUT_OF_ORDER`. The exact repeat of the last chunk (same seq **and** same SHA-256) is acknowledged without writing; anything else is refused.
- **Renderer:** `MediaRecorder.start(timeslice)` (1 s by default). Each chunk is queued and sent in order. The queue is **bounded** (32 MiB, PROVISIONAL): beyond it the capture stops with `BACKPRESSURE`, never growing in RAM. A blob is released once stored.
- **Backend:** never buffers the recording; each chunk is written and dropped. Tested: 96 MiB recorded in 1 MiB chunks → heap growth −3 to +1 MiB, read back in 64 KiB pieces.

## 6. State machine

| From | Allowed next states |
|---|---|
| PREPARING | RECORDING, FAILED, CANCELLED |
| RECORDING | FINALIZING, FAILED, CANCELLED |
| FINALIZING | READY, FAILED |
| READY | DELETING, MISSING |
| FAILED, CANCELLED | DELETING |
| MISSING | DELETING, READY (by recovery) |
| DELETING | DELETING (retry) |

- READY is reached **only** from FINALIZING. The DB refuses a READY row without storage key, checksum, size > 0, MIME and extension.
- A partial file is never READY.
- A **zero-byte** recording → `FAILED / EMPTY_RECORDING`, and its empty partial is removed.
- A very short valid recording is READY.

## 7. Atomic finalization and integrity

1. `fsync` of the partial descriptor.
2. `fstat` size must equal the bytes received.
3. **Streamed SHA-256** read back through the same descriptor (1 MiB buffer, never the whole file).
4. Checksum, size, MIME, extension and storage key are persisted **before** the rename.
5. Target must not exist (`FINALIZE_TARGET_EXISTS`).
6. **`rename` partial → files** (same root, same volume).
7. `lstat` of the final file: regular, size correct.
8. READY.

Any failure → FAILED with an honest code (`FINALIZE_FAILED`, `SIZE_MISMATCH`, …). The partial is kept and marked `recoverable`.

## 8. Crash recovery (`recoverAfterRestart`, boot-time)

- **PREPARING / RECORDING / FINALIZING without a live session:**
  - partial bytes > 0 → **FAILED / `INTERRUPTED_RECOVERY_REQUIRED`**, recoverable, bytes kept;
  - partial empty → FAILED / `INTERRUPTED_EMPTY`, empty partial removed.
  - Tested with a **real child process killed mid-capture**.
- **FINALIZING whose final file exists** (crash after the rename): READY **only if** the size and the pre-rename SHA-256 match (audited `RECORDING_RECOVERED`); otherwise FAILED.
- **READY whose file vanished** → MISSING.
- **Orphan files** (no catalogue row) are counted and reported, **never deleted or adopted silently**.
- **DELETING** rows are reported; only the user retries.
- **Idle sweep:** a session silent for 2 min (tab closed) → FAILED / `SESSION_ABANDONED`, bytes kept, and the single recording slot is released.
- **`shutdown()`:** active captures → FAILED, bytes kept.

## 9. Confinement

- **`resolveKey()`** is the only path builder:
  - strict key grammar `(files|partial)/rec_<32hex>.(webm|mp4|partial)`;
  - lexical containment under the **realpath** root (`path.relative`, not a string prefix);
  - the realpath of the parent directory must equal the expected Recorder directory, so a **junction / symlinked `files/` or `partial/` is refused** (`ROOT_ESCAPE`).
- **`RecorderStore.open`** refuses a redirected subdirectory.
- **Delete** never follows or deletes a link / non-regular file; it reports `DELETE_INCOMPLETE` instead.
- **Sentinel `RECORDER_SENTINEL_DO_NOT_TOUCH`** outside the root, byte-checked after every attack test. Tested inputs:
  - ids: `../`, `..\`, `%2e%2e`, double-encoded, `C:\`, UNC `\\server\share`, mixed separators, NUL, trailing dot / space, wrong case / length, objects;
  - crafted keys;
  - redirected directories (junctions, run on Windows) for write / open / delete;
  - HTTP-encoded traversal through the route.

  The sentinel was never written, deleted or opened.
- **File symlink sub-case:** NOT_APPLICABLE here (creating file symlinks on Windows needs a privilege the test process did not have); the code path refuses links (`LINK_REFUSED`).

## 10. Safe open (REC-DL-1 primitive) and TOCTOU

`openRecording(recordingId, { verifyChecksum })`:
1. id → READY row (`RECORDING_NOT_READY` / `RECORDING_FILE_MISSING` → row MISSING);
2. `resolveKey` (confinement);
3. `lstat`: not a link, a regular file;
4. open read-only (`O_NOFOLLOW` where the platform defines it);
5. **`fstat` on the descriptor** must show the same `dev` + `ino` (bigint) as the `lstat`, and the catalogue size;
6. optional streamed checksum through the descriptor;
7. returns `{ recordingId, mimeType, sizeBytes, filename, checksumSha256, fd, stream({start, end}), close() }`.

The caller streams **from the descriptor**, never by re-opening the path.

**Protection actually obtained:**
- A file swapped between the check and the open is **detected** (tested: `FILE_CHANGED`). Size / checksum tampering is detected (`SIZE_MISMATCH`, `CHECKSUM_MISMATCH`). A directory is refused (`NOT_REGULAR_FILE`).
- Once opened, a later rename / delete of the path cannot redirect the stream to another file.

**Limits:**
- Windows has no `O_NOFOLLOW`. Between the `lstat` and the open, a swap to a *link* is caught afterwards by the dev / ino comparison, not prevented.
- `dev` / `ino` on Windows come from the volume serial / NTFS file index (reliable on NTFS; not guaranteed on exotic filesystems).
- The bytes of an already-open file can still be modified in place by another local process with write access; `verifyChecksum` detects that only at open time.

No existing file-serving helper is reused for opening recordings: they are always streamed from the validated descriptor.

## 11. Deletion

- `deleteRecording(recordingId)` is refused while active (`RECORDING_ACTIVE`).
- It moves the row to DELETING, unlinks the final and partial files (confined, regular files only), checks they are absent, then removes the metadata row → `DELETED`. The audit keeps the id.
- Any file left → **`DELETE_INCOMPLETE`** with the stores and reasons, row kept in DELETING, retryable (tested with `EBUSY`).
- There is **no automatic purge** or retention.

## 12. Disk space, limits, errors

- **Disk space:** `statfs` free space is checked at session creation and before each chunk, keeping `minFreeBytes`. An OS `ENOSPC` also fails → **FAILED / `DISK_FULL`**, bytes kept and classified; other write errors give `WRITE_FAILED`. Never READY.
- **Limits** (all **PROVISIONAL**, with their basis in code):

| Limit | Value |
|---|---|
| `maxChunkBytes` | 8 MiB (also refused by the route before reading the body) |
| `maxRecordingBytes` | 2 GiB |
| `maxDurationMs` | 2 h |
| `maxActiveRecordings` | 1 |
| `minFreeBytes` | 512 MiB |
| `sessionIdleMs` | 2 min |
| `listLimit` | 100 |
| `titleChars` | 120 |
| renderer queue | 32 MiB |

## 13. Catalogue, list, audit, privacy

- **Catalogue:** a separate SQLite catalogue, schema v1, versioned migration ledger, **metadata only**. It does not touch the real `cortex.sqlite`, Notebook, Companion or KG. **New DB tables (in the Recorder catalogue only):** `recorder_recordings`, `recorder_audit`, `recorder_schema_migrations`.
- **`listRecordings({ limit ≤ 100, offset, status })`:** deterministic order (`created_at DESC, recording_id DESC`, indexed), `total` / `nextOffset`. No disk scan.
- **Audit** (append-only by trigger): `RECORDING_CREATED`, `STARTED`, `FINALIZED`, `FAILED`, `CANCELLED`, `DELETED`, `DELETE_INCOMPLETE`, `MARKED_MISSING`, `RECOVERY_FLAGGED`, `RECOVERED`. Details are ids, codes and sizes only; a detail containing a private path is refused.
- **Privacy:** a recording is private-local by nature. Nothing is sent to Companion, Notebook, KG or cloud; no automatic memory.

## 14. Isolated UI (`RecorderPanel`)

- **Controls:**
  - source Écran / Caméra, "Inclure le micro", optional title;
  - **Démarrer**; **Pause / Reprendre** only when `MediaRecorder.pause` exists (no fake pause); **Arrêter**; **Annuler**.
- **Indicator:** while capturing, a red **"ENREGISTREMENT EN COURS"** bar (`role="status"`) shows the source (+ micro), the elapsed time and its own **Arrêter** button. Focus moves to that Stop; Pause turns the bar amber.
- **Details:** camera preview (local only), format (WebM / MP4 + MIME), approximate size sent, result (title, duration, size, format) and errors by code.
- **Behaviour:**
  - capture only on "Démarrer" (no capture at load, tested);
  - Stop is prioritised: `MediaRecorder.stop()` + every track stopped at once, then the queue drains and finalize runs;
  - tracks are stopped on stop / cancel / error / unmount / partial permission refusal (tested);
  - the browser / OS ending the share fires the track's `ended` event → Stop + finalize (tested);
  - permission denied → `PERMISSION_DENIED`, no session, no READY;
  - one active recording per UI, and the server refuses a second session (`RECORDER_BUSY`).
- **Accessibility:** labelled radios / checkbox / input / video, keyboard Space / Enter (tested), real `disabled` states, visible focus. Reduced motion stops the blinking dot.
- **No download button.**

1. **`cortex-server/src/server.js`:** open `RecorderStore` on `<dirname(SQLITE_PATH)>/recordings`, run `recoverAfterRestart()` at boot (and `shutdown()` on stop), `app.route('/api', createRecorderRoute({ service }))`. It rides the NB-7 central guard; no body-cap exemption is needed.

## 17. Contract provided to REC-DL-1

- **`getRecording(recordingId)`** → public view, including `status`, `mimeType`, `sizeBytes`, `filename` (sanitized title + real extension) and `checksumSha256`.
- **`openRecording(recordingId, { verifyChecksum? })`** → a validated **descriptor** (READY only, confined, regular file, same dev + ino, catalogue size) with `stream({ start, end })` for ranges and `close()`. It never accepts a path.
- The internal storage locator (`storage_key`) stays server-side. `filename` is safe for `Content-Disposition` (no CR / LF / separators / quotes; Unicode kept for `filename*`).

## 18. Limitations

- **Real hardware not exercised:** `REAL_CAMERA_NOT_RUN`, `REAL_SCREEN_CAPTURE_NOT_RUN`. The camera / mic used Chromium's fake devices, and the screen was a synthetic canvas, so a person's screen is never captured by a test. Real `getDisplayMedia` prompts and OS share-stop UI are untested.
- **Track-level type unchecked:** the stored type is verified at **container** level (WebM / MP4 magic bytes), not at track level (an audio-only WebM would pass the sniff). Width / height / duration are **client-reported** (labelled `CLIENT_REPORTED`).
- **TOCTOU on Windows:** detection (dev + ino) rather than prevention between `lstat` and open (no `O_NOFOLLOW`); see §10.
- **`recoverable` is a classification, not a repair:** a FAILED recording with kept bytes has no repair tool yet. A cut WebM is often playable but not guaranteed.
- **Session state lives in process memory:** a restart ends live captures (classified at boot).
- **Disk space** uses `statfs` when available; otherwise only the OS `ENOSPC` protects.
- **All limits are PROVISIONAL.** There is no retention policy (by design).
- **Not wired; no download** (REC-DL-1 not resumed).

## REC-WIRE-1 — product wiring (2026-10-16)

RECORDER-1 is now wired into Docteur without a parallel store, service, route or navigation system.

- **Backend boot:** `server.js` opens `RecorderStore` at `<dirname(SQLITE_PATH)>/recordings`, creates the existing `RecorderService`, awaits `recoverAfterRestart()`, and mounts the existing `createRecorderRoute` below `/api`. A boot error leaves `/api/recorder/*` in a structured `503 RECORDER_UNAVAILABLE` state instead of claiming READY.
- **Guard/CORS:** Recorder routes inherit the existing central local API policy. The existing CORS allow-list now permits only the Recorder session-token header in addition to the previous headers. NB-7 proved hostile Origin/Host requests cannot reach non-frozen routes.
- **Shutdown:** the existing signal shutdown closes Recorder sessions/handles through `service.shutdown()` and then closes the Recorder catalogue.
- **Frontend:** `App.tsx` lazy-mounts the existing `RecorderPanel` inside the existing `StudioShell`; the central feature-open switch and `capabilities.ts` expose it through Help → **Fichiers et capture → Recorder**. `createHttpRecorderPort` uses the normal Docteur backend origin (`:3001`); the isolated product harness can select only a same-origin local Vite proxy. `cortex/client.ts` and global CSS remain untouched.
- **Unavailable UX:** the panel verifies the bounded metadata list before enabling Start. A failed check displays a safe Recorder-unavailable message and requests no camera/screen permission.
- **Product flow:** the new real-App Chromium harness opens Help, opens Recorder, records a synthetic screen through real `MediaRecorder`, sends multiple chunks, stops by keyboard, reaches READY, sees the recent item, downloads through the native browser manager, and compares the result byte-for-byte with `openRecording()` output. It reopens the same temporary catalogue and verifies listing plus download again.
- **Test isolation:** every product run uses an OS temporary Recorder root and synthetic screen. Real camera/screen, real user DB and real user recordings are not opened. External/cloud calls: 0.
- **Mixed files:** intentional unstaged Recorder hunks in `cortex-server/src/server.js`, `src/App.tsx`, and `src/content/capabilities.ts`. The pre-existing staged KG hunks and pre-existing App backup-restore hunks remain present. Index mutation commands: 0.

## RECORDER-CERT — final certification (2026-10-16)

RECORDER-CERT was validation-only. No Recorder, Companion, KG, Notebook/Frozen, or other product source file was changed; only this report and the REC-DL report were updated. The staged KG index remained outside the certification scope.

### Hardware and privacy boundary

- **Physical camera:** `REAL_CAMERA_NOT_RUN`.
- **Physical screen capture:** `REAL_SCREEN_CAPTURE_NOT_RUN`.
- **Physical microphone:** `REAL_MICROPHONE_NOT_RUN`.
- Reason: the available automation is intentionally unattended and privacy-preserving. Its Chromium launch uses fake camera/microphone devices, substitutes a synthetic canvas for screen capture, and explicitly rejects real `getDisplayMedia`. No attended browser/OS permission chooser or visual device-indicator observer was available, so the certification did not capture a person's camera, microphone, or screen and does not claim a physical-device result.
- Consequently, a physical-hardware READY recording, its download, and physical-source byte comparison are `NOT_RUN`. The equivalent isolated product flow passed with real browser `MediaRecorder`, synthetic/fake inputs, native download, and byte-for-byte comparison.
- Automatic capture remained zero at app load and at panel display. Capture occurred only after the tested user gesture. External network, cloud, Companion, Notebook, KG, and AI-provider transfers were zero in the Recorder harnesses.
- Physical camera/microphone indicators were not visually certified. Track cleanup is certified at the browser `MediaStreamTrack` contract level for Stop, Cancel, error, unmount/navigation, partial permission denial, and display-track `ended`.

### Runtime scope

- Every Recorder test and product run used a fresh OS temporary Recorder root. The real user DB hashes were recorded before validation, and no real user recording directory was used.
- `FULL_SERVER_PROCESS_NOT_RUN`: `server.js` also initializes unrelated services whose data roots are not all covered by one documented, complete temporary-root override. Starting it would not meet the mission's all-data-temporary guarantee. Boot/recovery/route/shutdown wiring is instead statically checked by the Recorder suite and exercised through the isolated service/route product harness.
- Restart persistence passed by closing and reopening the same temporary Recorder catalogue/service; the READY item remained listed and downloadable with an identical checksum.
- Interrupted/partial recovery passed in an isolated real child-process crash test: partial data became FAILED / `INTERRUPTED_RECOVERY_REQUIRED`, never silently READY. A post-rename crash is recovered only after checksum validation.
